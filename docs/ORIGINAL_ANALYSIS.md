# 원본(WP5_InspectionDT.html v8) 분석

원본은 압축된 번들이 아니라 **사람이 읽을 수 있는 JS 두 덩어리**(코어 약 500줄, 화면 약 920줄) + three.js r128 + 글꼴로 이뤄져 있다.
모사 시 옮겨야 할 대상은 코어 쪽이다.

## 2. 코어 4개 모듈

### KIN — 로봇 운동학 (가상 계산)
- 6축 산업용 로봇(도달 약 1.6 m, DH 파라미터 + 관절 한계). 실제 URDF는 미수령 상태(H2017 가정).
- `fk`(순기구학) · `ik`(감쇠 최소제곱, 최대 220회 반복) · `bestIK`(시드 5개로 재시도)
- `makeCtx(pose)`: 도킹 오차(dx, dy, dθ)를 반영한 셀 기하(AMR·판재·플랜지 상자)
- `clearance` · `transClear`: 링크(상완·전완·손목·툴)와 장애물 사이 여유거리
- 경로 생성: `scanPasses`(3D 스캔 P1~P5) · `visionPose(s)`(2D 촬영) · `utPath/utPathT`(초음파 주사)
- `solvePath` · `summary` · `tipError`: 경로를 풀어 도달성, 충돌 여유, 끝점 오차를 낸다

### GEOM — 시편 형상과 결함 (가상 데이터)
- 시편: 판재 300×200×16 mm, 용접선 x=150, 비드 폭 19 mm, 높이 2 mm, 플랜지 y 188~200
- 시편 A(정상) · B(모재 덴트 −1.22 mm) · C(비드 언더필, 언더컷, 기공 2, 균열 1, 융합불량)
- `devComp/dev`: 결함별 형상 편차 함수, `ROIS`: 3D 결과 ROI, `SPOTS`: 2D 촬영 지점과 결함 상자, `LOF`: 초음파 내부결함
- `shade`: 높이맵에 Blinn-Phong 조명을 적용한 가상 2D 영상

### SCEN — 시나리오 (타임라인 생성기)
- **시나리오는 JSON이 아니라 `build(sid)` 함수가 규칙으로 생성한다.** 시드 난수로 도킹 오차를 뽑는다.
- 정의(`DEF`): S1(시편 C, 결함 → 반품), S2(시편 A, 정상 → 적재), S3(시편 B, 덴트 → 반품)
- 흐름: 투입 → AMR-1이 3D 셀로 → 3D 스캔(품질 미달이면 재스캔) → 자율 분석(4단계) → 2D 셀로 → 2D 국부 촬영(재촬영) → 초음파 셀로 → 초음파(접촉 불량·기울어짐이면 재주사) → QC 판정 → 적재장 또는 반품 라인
- AMR-2는 다음 시편을 싣고 대기 구역에서 AMR-1이 비키기를 기다려 뒤따른다.
- 출력: `amrs`(구간 목록: move/dock/proc/hold/load/unload), `wins`(셀별 작업 구간), `events`(로그·메시지), `data`, `stages`
- 상수: AMR 속도 0.6 m/s, 도킹 4 s, 적재·하역 8 s, 셀 x좌표 3D −3.4 / 2D 0 / UT 3.4

### CODES — 계층, 공정, 데이터 코드
- 계층 7개: L0 통합 OCS, L1 운영·제어, L2 디지털트윈, L3 검사 AI, L4 데이터·통합, L5 엣지 수집, L6 설비·센서
- 공정 8개: 투입, 3D 스캔, 자율 분석, 2D 국부, 초음파, QC 판정, 이송·보고, AMR 물류
- **데이터 사전 D00~D30**(코드, 이름, 형식, 설명, 세부 코드, 저장 위치, 원천 계층, 분류)
  D00~D26은 초음파 DT와 공통, D27~D30은 플랫폼 확장안
- `build(SC)`: 시나리오 하나에 대해 "누가 누구에게 어떤 코드를 보냈나" 흐름 목록 `F`와 단위 공정 사이 전달 목록 `H`를 만든다

## 4. 모사 전략 (제안)

1. **데이터 사전과 계층을 JSON으로 추출** → `server/data/codes.json`, `layers.json` (코드 변경 없이 그대로 옮길 수 있음)
2. **GEOM(형상 · 결함)과 SCEN(시나리오 생성기)을 파이썬으로 이식** → `server/sim/` 과 `server/scenarios/`. 도킹 오차는 시드 고정 난수로 재현
3. **KIN(운동학)은 파이썬으로 이식하되 numpy 사용**. 실제 로봇이 정해지면 URDF 기반(`ikpy` 등)으로 교체
4. 서버는 `build()` 결과 전체(JSON)를 한 번 보내고, **타임라인 재생은 브라우저가 한다**(현재 뼈대의 30Hz 푸시는 센서 실시간용으로 남김)
5. 화면은 탭 구조부터 만들고, 탭별로 3D · canvas를 옮긴다
